  1. Перетаскивание изображений (reorder images)

  Твоя идея с drag-and-drop в Edit Mode — логичный подход. Вот мои мысли:

  Реализация: Каждый thumbnail получает draggable="true" в Edit Mode. При
  перетаскивании показываем визуальный индикатор места вставки (линия между
  изображениями). При drop — обновляем массив images в metadata.

  Edit Mode ON:
    Batch 3
    ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐
    │ img1 │ │ img2 ▓│▓img3 │ │ img4 │   ← тащим img5 сюда
    │  ☐   │ │  ☑   │ │  ☐  │ │  ☐   │      (линия-индикатор)
    └──────┘ └──────┘ └──────┘ └──────┘
                       ↕
    Batch 2
    ┌──────┐ ┌──────┐ ┌──────┐
    │ img5 │ │ img6 │ │ img7 │   ← можно перетащить и сюда
    │  ☐   │ │  ☐   │ │  ☐   │
    └──────┘ └──────┘ └──────┘

  Ключевые моменты:

  - Перетаскивание между батчами — это, по сути, удаление из одного batch.images
   и вставка в другой. Нужен один API-эндпоинт типа POST 
  /api/tabs/:name/reorder-images, который принимает полную новую конфигурацию
  затронутых батчей.
  - Мультиселект + drag — если выбрано несколько изображений и пользователь
  начинает тащить одно из выбранных, перетаскиваются все выбранные. Визуально
  можно показать бейдж с числом: [3] на курсоре. Если тащат невыбранное —
  перетаскивается только оно одно (стандартное поведение как в Finder/Explorer).
  - Важный нюанс: при перетаскивании между батчами изображение физически
  остаётся в той же папке (все изображения таба лежат в одной директории),
  меняется только запись в metadata.json. Это упрощает реализацию.

  Альтернатива drag-and-drop: кнопки "Move up/down" на каждом изображении. Но
  это неудобно для больших батчей и не позволяет переносить между батчами.
  Drag-and-drop — лучший вариант.

  Мои предложения по улучшению:
  - При перетаскивании в зону другого батча, подсветить весь батч-контейнер
  рамкой, чтобы было видно "куда попадёт".
  - При множественном перетаскивании показывать полупрозрачный "стак" из
  нескольких миниатюр.

  2. Перетаскивание табов (reorder tabs)

  Тоже логично через drag-and-drop в Edit Mode.

  Edit Mode ON:
    [Tab1 ✕] [Tab2 ✕] ▓ [Tab3 ✕] ▓ [Tab4 ✕]   [➕ New]
                        ↑
                тащим Tab3 сюда (линия-индикатор между табами)

  Реализация:
  - Табы получают draggable="true" в Edit Mode.
  - При drop — меняется порядок в массиве metadata.tabs.
  - Нужен API-эндпоинт PUT /api/tabs/reorder принимающий новый порядок (массив
  имён табов).
  - Батчи внутри табов не затрагиваются — меняется только индекс таба в массиве.

  Это самая простая из четырёх задач. Минимальный объём кода.

  ---
  3. Перетаскивание батчей (reorder batches + move between tabs)

  Здесь две подзадачи:

  3a. Порядок батчей внутри таба

  Аналогично изображениям — drag-and-drop целых блоков .batch в Edit Mode.
  Визуальный индикатор — горизонтальная линия между батчами.

  Edit Mode ON:
    ┌─ Batch 3 ─────────────────────┐
    │  img1  img2  img3             │  ← схватили за заголовок
    └───────────────────────────────┘
    ═══════════════════════════════════  ← индикатор вставки
    ┌─ Batch 2 ─────────────────────┐
    │  img4  img5                   │
    └───────────────────────────────┘
    ┌─ Batch 1 ─────────────────────┐
    │  img6  img7  img8             │
    └───────────────────────────────┘

  Реализация:
  - Перетаскивание за .batch-header (заголовок батча).
  - API: PUT /api/tabs/:name/reorder-batches — принимает новый порядок индексов.

  3b. Перенос батча в другой таб

  Это интереснее, потому что drag-and-drop батча на таб в tab-bar будет
  неудобным — батч-блок большой, а таб маленький, и при перетаскивании батча
  пользователь "уходит" с текущего таба визуально.

  Мои варианты:

  Вариант A — Контекстное меню "Move to tab" (рекомендую):
  В Edit Mode у каждого батча добавляется кнопка [📁→] или [Move]. По клику
  открывается компактный dropdown с списком табов:

    Batch 3 · 2/21/2026     [Copy] [Move ▾] [+] [🗑️]
                              ┌──────────┐
                              │ Spring   │
                              │ Summer   │
                              │ Autumn   │  ← выбрать таб
                              │ Winter   │
                              └──────────┘

  Плюсы: просто, понятно, не конфликтует с drag-and-drop батчей внутри таба.
  Одно нажатие + выбор таба.

  Вариант B — Drag на таб:
  Тащим батч на таб в tab-bar. Проблема: при drag батча за заголовок уже
  используется для reorder внутри таба. Можно различать: если drop на .tab —
  перенос в другой таб, если drop между батчами — reorder. Но UX получается
  запутанный.

  Вариант C — Кнопки-стрелки:
  [◀ Tab] и [Tab ▶] для переноса в соседний таб. Слишком ограничено если табов
   много.

  Рекомендация: Вариант A (dropdown "Move to tab") — самый чистый UX. Он не
  конфликтует с drag-and-drop reorder и интуитивно понятен.

  Важный нюанс: при переносе батча между табами нужно физически переместить
  файлы изображений из одной папки в другую (в отличие от reorder изображений
  внутри таба). Это требует серверной логики.

  ---
  4. Кнопка Copy Title

  Самое простое из всего. Добавить кнопку "Copy Title" слева от "Copy Prompt".

    Batch 3 · 2/21/2026     [Copy Title] [Copy Prompt] [+] [🗑️]

  Нюанс: сейчас кнопка Copy копирует description (промпт). Предлагаю:
  - Переименовать текущую "Copy" → "Copy Prompt" (для ясности).
  - Добавить "Copy Title" рядом, которая копирует batch.title.
  - Обе кнопки показывают "Copied!" на 1.5 секунды после клика.
  - Если title пустой — кнопка Copy Title может быть скрыта или disabled.

  По поводу твоего вопроса о Copy Title — кнопка "Copy prompt" уже так и
  называется в UI (Copy prompt), так что переименовывать ничего не нужно. Новая
  кнопка "Copy title" встанет слева от неё.

  Краткое резюме финализированного плана:

  1. Reorder images — drag-and-drop thumbnails в Edit Mode, с поддержкой
  мультиселекта (бейдж с числом), перенос между батчами в рамках одного таба.
  Пустые батчи сохраняются.
  2. Reorder tabs — drag-and-drop табов в Edit Mode, вертикальный индикатор
  между табами.
  3. Reorder batches — кнопка [Move] слева от заголовка как drag handle. Move to
   dropdown для переноса батча в другой таб (батч добавляется на самый верх
  целевого таба). Файлы физически перемещаются на сервере.
  4. Copy Title — кнопка [Copy title] слева от [Copy prompt], всегда видима,
  одинаковый стиль.

  4 новых API-эндпоинта, нативный HTML5 DnD, без внешних зависимостей. Все
  детали, включая формат API-запросов, CSS-классы и edge cases — в документе.
